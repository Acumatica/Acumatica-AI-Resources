# Access for Acumatica Support {#_4b7673ae-df66-42e8-ae1b-b2d8d7bde4da .reference}

Form ID: \(SM202065\)

You use this form to manage support access to the current tenant for the Acumatica support user, *AcumaticaSupport*. On this form, access can be only managed or revoked, but not granted. To manage access for *AcumaticaSupport* to a specific tenant, the administrator must be signed in to this tenant.

A Partner Portal user can grant access for *AcumaticaSupport* from the Partner Portal only.

## Form Toolbar { .section}

The form toolbar includes the buttons described below.

|Button|Description|
|------|-----------|
|**Revoke Access**|Revokes access to the current tenant for *AcumaticaSupport* by deleting the temporary secret key that was generated when access was granted. This button is unavailable if **Access Status** is set to *Revoked*.

When you invoke this action, the system changes **Access Status** to *Revoked*.

|
|**Disable User**|Disables the *AcumaticaSupport* user account. Disabling this user account prevents it from signing in to the current tenant. To enable this user account again if it has been deactivated, you need to use the [Users](SM_20_10_10.md) \(SM201010\) form.This button is displayed on the form toolbar if **Support User Status** is set to *Active* \(that is, *AcumaticaSupport* is active\).

When you invoke this action, the system changes **Support User Status** to *Inactive*, and this button is replaced by the **Enable User** button.

|
|**Enable User**|Enables the *AcumaticaSupport* user account. This button is displayed on the form toolbar if **Support User Status** is set to *Inactive* \(that is, *AcumaticaSupport* is inactive\).

When you invoke this action, the system changes **Support User Status** to *Active*, and this button is replaced by the **Disable User** button.

|

## Summary Area {#1 .section}

The informational elements in this area show the status of *AcumaticaSupport* and the status of the support access to the current tenant.

|Element|Description|
|-------|-----------|
|**Support User Status**|Read-only. The status of *AcumaticaSupport*, which is used as a proxy to access the customer site. This box contains one of the following values: *Active* or *Inactive*.|
|**Access Status**|Read-only. The status of the Acumatica support engineer's access to the customer site. This box contains one of the following values: *Granted* or *Revoked*.|
|**Allow Support to Sign In as Any User**|A check box that indicates \(if selected\) that if the *AcumaticaSupport* user signs in to the system, the **Sign In as User** button becomes available to them on the [Users](SM_20_10_10.md) \(SM201010\) form.

 **Attention:** By using the **Sign In as User** button, the *AcumaticaSupport* user may sign in as a user with the *Administrator* role, which effectively grants them full access to the system.

 The check box is cleared by default.

|

## Roles Granted Tab { .section}

By default, the *AcumaticaSupport* user has only one role selected, *AcumaticaSupport*. This tab allows you to select and clear roles for the *AcumaticaSupport* user. The initially selected *AcumaticaSupport* role is a specific role for the *AcumaticaSupport* user.

**Note:** The roles for *AcumaticaSupport* also can be managed on the [Users](SM_20_10_10.md) \(SM201010\) form.

The table toolbar includes only standard buttons.

|Column|Description|
|------|-----------|
|**Selected**|A check box that you select to grant access to the role for *AcumaticaSupport*.|
|**Role Name**|Read-only. The name that identifies the role.|
|**Role Description**|Read-only. The description of the role.|

## History Tab { .section}

This tab contains information about the granting and revoking of access and the permission to sign in as any user through the [Users](SM_20_10_10.md) \(SM201010\) form. It presents a history of what user performed the action, such as granting or revoking access, and when this action occurred.

The table toolbar includes only standard buttons.

|Column|Description|
|------|-----------|
|**Person**|The person that performed the action specified in the **Action** column.|
|**Action**|The action performed, which is one of the following: *Granted*, *Revoked*, *Allowed Login as Any User*, or *Forbade Login as Any User*.|
|**Date**|The date when this action was performed.|

## User Trace Tab { .section}

This tab contains information about the access of Acumatica support engineers to the specific customer's instance. If the support user signed in as a different user by using the **Sign In as User** button on the [Users](SM_20_10_10.md) \(SM201010\) form and performed activities on behalf of that user, the records in the table reflect this information as well.

The table toolbar includes only standard buttons.

|Column|Description|
|------|-----------|
|**Date**|The date and time of the activity.|
|**Username**|The name of the support user who performed the activity and, if applicable, the name of the user on whose behalf the activity was performed.|
|**Operation**|The operation performed by the user.|
|**Host**|The system host.|
|**IP Address**|The IP address from which the user signed in to the system.|
|**Screen ID**|The screen ID of the form that was accessed by the user.|
|**Title**|The name of the form that was accessed by the user.|
|**Comment**|The automatically generated comment.|
