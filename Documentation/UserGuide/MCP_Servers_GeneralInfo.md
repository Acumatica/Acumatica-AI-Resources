# Configuring MCP Servers: General Information

You can configure Model Context Protocol \(MCP\) servers so that external MCP clients can discover and call selected tools in Acumatica ERP. For example, your organization can use an MCP server to let an AI client retrieve data from selected generic inquiries and analyze this data outside Acumatica ERP.

Each MCP server contains a focused set of tools. In Acumatica ERP, a *Generic Inquiry* tool retrieves data from one published generic inquiry.

**Tip:** We recommend limiting each MCP server to 50 tools or fewer. A smaller tool set makes it easier for an AI model to identify and call the right tool.

## Preparation for the Configuration

Before you begin configuring MCP servers, make sure that the following is true:

-   The *MCP Server* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form. The feature is available under *AI Studio*.
-   The generic inquiries that you want to expose as tools are published to the UI.
-   The users who will connect through an MCP client have access to the generic inquiries that the tools use.

## MCP Server Configuration

You configure MCP servers on the [MCP Servers](SM_30_21_00.md) \(SM302100\) form. This form is in the **Preferences** category of the **Integration** workspace, as shown below.


On the form, you can create a server \(Item 1 below\), make it active \(Item 2\), copy its URL \(Item 3\), and specify a title \(Item 4\) and instructions \(Item 5\) for the server.

The instructions can describe the purpose of the server and the ways clients are expected to use its tools. MCP clients that support server instructions can use this text when deciding how to work with the server. However, AI clients, such as Claude and ChatGPT, currently don’t use this field.

The server URL is generated by the system. You provide this URL to the AI client when you configure the connection.

The form also includes the **Tools** grid \(Item 6\) and a settings panel \(Item 7\) for the selected tool. Currently, *Generic Inquiry* \(Item 8\) is the only supported tool type.


You can export MCP server configurations to XML and import them from XML. Generic inquiry definitions are exported separately from the [Generic Inquiry](SM_20_80_00.md) \(SM208000\) form.

## Generic Inquiry Tools

To make generic inquiry data available to an MCP client, you add a tool of the *Generic Inquiry* type to the MCP server. Each tool is based on one published generic inquiry.

For each tool, you specify the following settings:

-   **Tool Type** \(Item 1 below\): *Generic Inquiry*
-   **Generic Inquiry** \(Item 2\): The published generic inquiry that the tool uses as the data source
-   **Tool Name** \(Item 3\): The name that the MCP client uses to identify and call the tool

You may also specify the following optional settings:

-   **Tool Title** \(Item 4\): The human-readable title of the tool. By default, the **Tool Title** column is populated with the site map title of the selected generic inquiry, but you can change it.
-   **Shared Filter to Apply** \(Item 5\): The shared filter that is applied when the tool is called, if any.


The MCP client uses the **Tool Name** to identify and call the tool. The name must meet the following requirements:

-   It must be unique within the MCP server.
-   It is case-sensitive.
-   It can be from 1 to 64 characters long.
-   It can contain only uppercase and lowercase ASCII letters, digits, underscores, and hyphens.
-   It can’t contain spaces, periods, commas, or other special characters.

**Tip:** Use a short, descriptive tool name that reflects the data or task the tool supports. Meaningful names help AI models identify the appropriate tool.

## Generated Tool Schemas

For each *Generic Inquiry* tool, the system generates a tool description and input and output schemas from the generic inquiry definition. Together, these elements tell MCP clients which values they can provide and what data the tool can return. The description includes information about the generic inquiry fields, which is especially important because AI clients such as Claude and ChatGPT may rely on the description rather than the output schema when deciding how to use the tool.

Visible result columns and key fields become output fields, while visible and active generic inquiry parameters become tool input parameters. The system maps generic inquiry field types to the corresponding JSON Schema types.

The generated input schema includes the following built-in query options:

-   `skip`: Skips a specified number of records, typically for pagination
-   `top`: Limits the number of records returned in one response
-   `select`: Returns only the specified fields
-   `orderBy`: Sorts the returned records
-   `filter`: Filters records
-   `parameters`: Supplies values for parameters defined in the generic inquiry

The generated output schema uses the `count` property for the total number of matching records and the `value` property for the returned rows. If `select` is specified in the request, each row contains only the selected fields. Otherwise, all visible result columns are returned.

**Attention:** Generated tool schemas are not fixed contracts. They may change between Acumatica ERP releases without a separate change notification.

## Access Rights and Logging

MCP clients authenticate through OAuth 2.0. Each request is made on behalf of the signed-in Acumatica ERP user, so the user can access only the tools and data permitted by their access rights.

When a user connects to an MCP server, the server returns only tools for generic inquiries that the user is permitted to access. The system checks the user's access rights again each time an MCP client calls a tool.

If access to a generic inquiry is revoked, the user can no longer retrieve data through the related tool. If access is granted, the user may need to refresh the MCP client's tool list before the tool becomes available.

If the generic inquiry that is used by a *Generic Inquiry* tool is somehow broken and cannot be opened in Acumatica ERP, the tool still appears during tool discovery in the connected client, but its title begins with *\(Unavailable\)*. If an MCP client attempts to call the tool, the client receives the following error: *The \{0\} tool is currently unavailable. Contact the MCP server administrator.*

MCP tool calls are always logged. You can review the logged calls on the [Access History](SM_20_10_45.md) \(SM201045\) form by selecting *MCP Tool Call* in the **Operation** box.
