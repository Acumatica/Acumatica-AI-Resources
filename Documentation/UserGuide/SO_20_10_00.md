# Order Types {#_e6984218-4260-4438-99e1-aee2b3765369 .reference}

Form ID: \(SO201000\)

**Attention:** This form is available only if the *Inventory and Order Management* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

You can use this form to view the settings of the available order types. Acumatica ERP provides predefined order types to cover the most common order types, and the settings of any type can be changed to meet your company's needs. For descriptions of the predefined order types, see [Sales Order Types: General Information](../ImplementationGuide/config_Sales_Order_Types_GeneralInfo.md).

If the *Custom Order Types* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form, you can create a new order type based on any of the predefined order templates, or create a new order type from scratch. For details about creating custom order types, see [Sales Order Types: Custom Sales Order Types](../ImplementationGuide/config_Sales_Order_Types_Custom_Order_Types.md).

On the [Sales Orders](SO_30_10_00.md) \(SO301000\) form, users can create orders of all active types: the types predefined in Acumatica ERP, and any custom order types \(if this feature is enabled in your system\).

## Form Toolbar { .section}

The form toolbar has only standard buttons.

## Summary Area {#1 .section}

This area provides summary information about the order type. In this area, you can select an available order type and view and edit its settings.

|Element|Description|
|-------|-----------|
|**Order Type**|The identifier of the order type, which is a two-character alphanumeric string. Acumatica ERP provides the following predefined order types: -   *BL \(Blanket Order\)*: Documents of this type are used to record planned sales of large quantities of items according to a long-time agreement between the selling and purchasing companies.
-   *CM \(Credit Memo\)*: Documents of this type are used as adjustments to already-completed sales orders when the customer returns goods without advance authorization.
-   *CR \(Cash Return\)*: Documents of this type are used to register returns from cash sales that did not involve shipping.
-   *CS \(Cash Sale\)*: Documents of this type are used to register cash sales.
-   *IN \(Invoice\)*: Documents of this type are used to bill a customer for shipped goods.
-   *MO \(Mixed Order\)*: Documents of this type are used to record both a sale and a return in the same order.
-   *QT \(Quote\)*: Documents of this type are used to register a customer's intention to buy goods in the specified quantity, on the specified date, and at the specified price.
-   *RC \(Return for Credit\)*: Documents of this type are used to register authorized customer returns for credit without replacement.

This option appears only if the *Inventory* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

-   *RM \(RMA Order\)*: Documents of this type are used to register authorized customer returns for replacement or credit within the warranty period of a product.

This option appears only if the *Inventory* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

-   *RR \(Return with Replacement\)*: Documents of this type are used to register authorized customer returns for replacement.

This option appears only if the *Inventory* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

-   *SA \(Sales Order with Allocation\)*: You have to manually allocate the ordered quantities of the items at one location or multiple locations if the available quantity at the specified location is less than the ordered quantity. Once you save an order of this type, the quantities of items are added to the *SO Allocated* plan types.

This option appears only if at least one of the following features is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form: the *Lot and Serial Tracking*, *Multiple Warehouse Locations*, *Sales Order to Purchase Order Link*, and *Inventory Replenishment*.

For details, see [Availability Calculation Rules: General Information](Availability_Calculation_Rules_GeneralInfo.md).

-   *SO \(Sales Order\)*: Documents of this type are created to record customer requests to purchase goods and are used to prepare shipments.

This option appears only if the *Inventory* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

-   *TR \(Transfer\)*: Documents of this type are generated to perform stock replenishment by transferring goods from the source warehouse.

This option appears only if the *Multiple Warehouses* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

-   *CS \(Cash Sale\)*: The built-in template for the *CS* order type.
-   *IN \(Invoice\)*: The built-in template for the *IN* order type.
-   *MO \(Mixed Order\)*: The built-in template for the *MO* order type.
-   *QT \(Quote\)*: The built-in template for the *QT* order type.
-   *RC \(Return for Credit\)*: The built-in template for the *RC* order type.
-   *RM \(RMA Order\)*: The built-in template for the *RM* order type.
-   *RR \(Return with Replacement\)*: The built-in template for the *RR* order type.
-   *SA \(Sales Order with Allocation\)*: The built-in template for the *SA* order type.

This option appears only if at least one of the following features is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form: *Lot and Serial Tracking*, *Multiple Warehouse Locations*, *Sales Order to Purchase Order Link*, and *Inventory Replenishment*.

-   *SO \(Sales Order\)*: The built-in template for the *SO* order type

If the *Custom Order Types* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form, you can create a new order type based on any of the predefined order templates, or create a new order type from scratch. ## General Tab {#2 .section}

This tab contains settings that hold details about the order type.

|Element|Description|
|-------|-----------|
|**Order Numbering Sequence**|The numbering sequence to be used to automatically generate reference numbers for documents of this type.|
|**Days To Keep**|The number of days documents of the type should be kept in the system before they can be selected for canceling on the [Process Orders](SO_50_10_00.md) \(SO501000\) form.

 Based on this date, the **Cancel By** date on the [Sales Orders](SO_30_10_00.md) \(SO301000\) form is calculated. If the value is *0*, this date is equal to the current business date.

|
|**Hold Orders on Entry**|A check box that indicates \(if selected\) that the system should save documents of the type with the *On Hold* status by default.|
|**Hold Document on Failed Credit Check**|A check box that indicates \(if selected\) that the system will change the status of the order to *Credit Hold* if the customer fails the credit check. The credit check is performed each time the order is saved.

 This check box is available for editing if the selected order type has the *Sales Order*, *Invoice*, *Mixed Order*, or *RMA Order* automation behavior specified on the **Template** tab of the current form.

|
|**Remove Credit Hold on Payment Application**|A check box that indicates \(if selected\) that the system will automatically remove a sales order of the type from credit hold when a payment has been applied to the full order amount. The system automatically selects this check box when a user selects **Hold Documents on Failed Credit Check** for the order type, but you can clear it.

 If you clear the **Remove Credit Hold on Payment Application** check box for the order type, the *Credit Hold* status will remain unchanged in the sales order when the payment has been applied to the full order amount. In this case, the user can change the *Credit Hold* status in either of the following ways:

 -   For an individual order by opening the order on the [Sales Orders](SO_30_10_00.md) \(SO301000\) form and clicking the **Remove Credit Hold** command on the More menu
-   For any number of orders by selecting the *Remove Credit Hold* action on the [Process Orders](SO_50_10_00.md) \(SO501000\) form and processing the needed orders

 **Attention:** If the customer specified in a sales order has the *Credit Hold* status on the [Customers](AR_30_30_00.md) \(AR303000\) form, the sales order cannot be moved from the *Credit Hold* status. It maintains this status even if the **Remove Credit Hold on Payment Application** check box is selected for the order type on the current form and a payment has been applied to the full order amount. The status of the order can be changed only when the customer's status is no longer *Credit Hold*.

|
|**Require Control Total**|A check box that indicates \(if selected\) that you must enter an amount in the **Control Total** box on the [Sales Orders](SO_30_10_00.md) \(SO301000\) form before you can save the order with the *Open* status. The control amount must match the value in the **Order Total** box, which is the total amount of the document.

 This check box is unavailable for order types with the *Transfer Order* automation behavior on the **Template** tab.

|
|**Bill Separately**|A check box that indicates \(if selected\) that each order of this type should be billed separately from other orders of the same type.

 This check box is available for editing if the selected order type has the *Sales Order* or *Invoice* automation behavior specified on the **Template** tab of the current form. For an order type with the *RMA Order* or *Credit Memo* automation behavior, this check box is available for editing if **AR Document Type** has a value other than *No Update* on the **Template** tab. For an order type with the *Mixed Order* automation behavior, this check box is selected by default and unavailable for editing.

|
|**Ship Separately**|A check box that indicates \(if selected\) that the goods for each order of this type should be shipped separately from goods for other orders of the same type.

 **Attention:** Orders of the type for which the **Ship Separately** check box is selected can still be consolidated to a single shipment if you manually add them by clicking **Add Order** on the table toolbar of the **Details** tab of the [Shipments](SO_30_20_00.md) \(SO302000\) form.

 This check box appears only if the *Inventory* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

|
|**Calculate Freight**|A check box that indicates \(if selected\) that the freight for each order of this type should be calculated.|
|**Ship in Full if Negative Quantity Is Allowed**|A check box that indicates \(if selected\) that the system will create a shipment that includes stock items for which a negative quantity is allowed for the entire line quantity, regardless of whether this quantity is in stock. A negative quantity is allowed for an item if it belongs to an item class that has the **Allow Negative Quantity** check box selected on the [Item Classes](IN_20_10_00.md) \(IN201000\) form.

 This setting is applicable to sales order lines with stock items that are not serialized and to sales order lines with serialized items that have the *When Used* assignment method.

|
|**Disable Automatic Discount Update**|A check box that indicates \(if selected\) that the system treats already-applied discounts to an order of the type as manual. When a user runs discount recalculation or adds new lines to the order on the [Sales Orders](SO_30_10_00.md) \(SO301000\) form, the system preserves the set of applied discounts; it checks whether these discounts are still applicable for the order, but does not apply any other new discounts to the order. If a user manually changes any of the discountable amounts or quantities in the order, the system recalculates the fixed set of applied discounts based on these changes.

 If the check box is cleared for the order type, the system refreshes all automatic line, group, and document discounts.

|
|**Recalculate Discount on Partial Shipment**|A check box that indicates \(if selected\) that if an order of the type is shipped partially, the system should recalculate the discount for each shipment based on each shipment amount or shipment quantity.

 **Attention:**

-   Recalculation does not involve discounts that consist of free items.
-   If partial invoices have been prepared for an order of the type, the system does not split manual discounts across these invoices, and the discount amount and discount percent in the invoices on the [Invoices](SO_30_30_00.md) \(SO301000\) form remain empty. The system keeps manual discounts only if the invoice includes all the lines from a sales order that has been fully shipped.

 This check box is available only if the *Customer Discounts* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

 This check box appears if the order type has the *Sales Order*, *Invoice*, *Credit Memo*, *Mixed Order*, or *RMA Order* automation behavior specified on the **Template** tab of the current form.

|
|**Disable Automatic Tax Calculation**|A check box that indicates \(if selected\) that the system will select the **Disable Automatic Tax Calculation** check box by default on the **Financial** tab of the [Sales Orders](SO_30_10_00.md) \(SO301000\) form for new sales orders of the current type.

 The check box can be selected for the order types that will be used for orders imported from e-сommerce stores, or for orders in which taxes will be specified manually.

 This check box appears if the order type has the *Sales Order*, *Invoice*, *Quote*, *Credit Memo*, *Mixed Order*, or *RMA Order* automation behavior specified on the **Template** tab of the current form.

 If integration with an external tax provider is configured, the order has the external tax provider specified as the customer tax zone, and this check box is selected, Acumatica ERP does not send API requests for taxes to the tax service.

|
|**Allow Refund Before Return**|A check box that indicates \(if selected\) that a refund can be created on the [Sales Orders](SO_30_10_00.md) \(SO301000\) form for a sales order of the selected type that has the *Open* status.

 If the order type has the *RMA Order* or *Credit Memo* automation behavior, this check box is available for editing if **AR Document Type** contains a value other than *No Update* and in the **Operations** table, there is no active operation of the *Issue* type.

 If the order type has the *Mixed Order* automation behavior, this check box is selected by default and unavailable for editing.

|
|**Require Customer Order Nbr.**|A check box that indicates \(if selected\) that users must fill in the **Customer Order Nbr.** box on the [Sales Orders](SO_30_10_00.md) \(SO301000\) form when they are entering new orders of this type. In this case, the system generates an error if the **Customer Order Nbr.** box is not filled in and validates the entered number for uniqueness, based on the option selected in the**Customer Order Nbr. Validation** box of the current form. If this check box is cleared, the system does not ensure that the customer order number is specified and does not validate customer order numbers when an order of the type is saved.

 This check box appears if the order type has the *Sales Order*, *Invoice*, *Quote*, *Credit Memo*, *Mixed Order*, or *RMA Order* automation behavior specified on the **Template** tab of the current form. If the order type has the *Transfer Order* automation behavior specified, this check box is cleared by default and unavailable for editing.

|
|**Customer Order Nbr. Validation**|The way the system validates the customer order number that the user enters on the [Sales Orders](SO_30_10_00.md) \(SO301000\) form in a sales order of this type.

 You can select one of the following values:

 -   *Allow Duplicates*: The system allows the user to enter duplicate customer order numbers on sales orders \(that is, the same customer order number can be entered on multiple sales orders\).
-   *Warn About Duplicates*: If a user enters a customer order number that has already been specified in another sales order, the system generates a warning but allows the duplicate number.
-   *Forbid Duplicates*: The system displays an error message when a user enters a customer order number that has already been specified in any other sales order. The entered document cannot be saved until the user specifies a unique customer order number.

 This box is available for editing if the **Require Customer Order Nbr.** check box is selected. If the check box is cleared, the *Allow Duplicates* option is selected and cannot be changed.

|
|**Protect Personal Data**|A check box that indicates \(if selected\) that personal data in the sales orders of that type, as well as related invoices and shipments, can be erased or pseudonymized on the [Protect Personal Data](BC_50_20_00.md) \(BC502000\) form. This personal data includes the ship-to address, bill-to address, ship-to contact, and bill-to contact settings. These are displayed on the **Addresses** tab of the [Sales Orders](SO_30_10_00.md) \(SO301000\), [Shipments](SO_30_20_00.md) \(SO302000\), and [Invoices](SO_30_30_00.md) \(SO303000\) forms.

 The check box must be selected for seller-fulfilled orders imported from Amazon stores because of Amazon's requirement to not store the customer's personal data in an imported order and its related shipment and invoice for more than 30 days after the order's creation.

 **Important:**

-   This check box appears on the form only if the *Retail Commerce* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.
-   You can select this check box for an order type only if the Acumatica ERP database is encrypted with an algorithm with a minimum of 2048-bit encryption. For an overview of encrypting data in Acumatica ERP, see [Digital Certificates: General Information](SA_Data_Encryption_GeneralInfo.md).

 -   *Invoice*
-   *Debit Memo*
-   *Credit Memo*
