# Case

Form ID: \(SP401000\)

**Who uses this form:** An authorized portal user of a company using the Modern Customer Portal.

In the Modern Customer Portal, you use this form to manage an individual support case, which is integrated with Acumatica ERP’s case management capabilities. You can open this form by clicking a case on the [Cases](SP_40_10_10.md) \(SP401010\) form.

On this form, you can create a case, submit it to the portal owner’s support team, track the status of the case, or communicate with the support team through case messages. Members of the support team view and manage these cases in Acumatica ERP.

This form is available only if both of the following conditions are met for the portal owner:

-   The *Modern Customer Portal* and *Case Management* features are enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.
-   The portal has the **Case Management** check box selected on the **General** tab of the [Portals](SP_70_10_00.md) \(SP701000\) form.

 You can assign to the case one of the following options: *Low*, *Medium* \(default\), *High*, or *Urgent*.

</td></tr><tr><td>

**Summary**

</td><td>

A short description of the case. You must enter a summary before you submit the case.

</td></tr><tr><td>

**Case Class**

</td><td>

The class of the case, which determines its workflow.

 For a new case, this box is filled in with the portal’s default class, which is specified on the [Portals](SP_70_10_00.md) \(SP701000\) form. The system populates some elements with the default values of the class, easing data entry. You can select a different class.

</td></tr><tr><td>

**Business Account**

</td><td>

The name of your company’s business account. The box appears only after the case has been submitted.

 The system fills in this box with the business account specified on the [Contacts](CR_30_20_00.md) \(CR302000\) form for the portal user. You cannot override this value.

</td></tr><tr><td>

**Contract**

</td><td>

The contract associated with the business account and the case. You can click the magnifier button and select a contract. The box appears only after the case has been submitted.

</td></tr><tr><td>

**Contact**

</td><td>

The employee of your company to be contacted about the case. The case creator is inserted by default. You can click the magnifier button and select a different contact.

</td></tr><tr><td>

**Status**

</td><td>

The status of the case, which the system inserts based on user actions as the case is processed. The box appears only after the case has been submitted.

 The status can be one of the following:

 -   *New*: The case has been created and submitted in the portal, but no work has been done on it yet.
-   *Open*: The case is being worked on by the portal owner’s support team.
-   *Pending Customer*: The portal owner’s support team is waiting for feedback or a response from a portal user.
-   *Closed*: Your company's problem has been resolved, a solution has been found, or no further work is expected to be done on the case.

</td></tr><tr><td>

**Reason**

</td><td>

The reason for the status of the case. The box is visible only after the case has been submitted. The case owner \(a support team member\) assigns this value to the case. Only particular reasons are available for selection, based on the most recent action performed on the case.

 The reason can be one of the following:

 -   *Unassigned* \(default\): The new case has not been assigned to the case owner. A case with this reason has the *New* status.
-   *Assigned*: The case has been assigned to the case owner. A case with this reason has the *New* or *Open* status.
-   *Opened on Portal*: A portal user reopened a formerly closed case or sent a message for it, which causes it to be reopened. A case with this reason has the *Open* status.
-   *In Process*: The case is being worked on. A case with this reason has the *Open* status.
-   *Updated*: The case has been updated with new details or changed settings. A case with this reason has the *Open* status.
-   *In Escalation*: The case has been escalated. A case with this reason has the *Open* status.
-   *Pending Closure*: The case is ready to be closed by a portal user. A case with this reason has the *Open* or *Pending Customer* status.
-   *More Info Requested*: The case owner has sent a request for additional information to find a solution to the case. A case with this reason has the *Pending Customer* status.
-   *Waiting Confirmation*: A solution to the case has been found; the case is ready for closure and is awaiting confirmation from the portal user. A case with this reason has the *Pending Customer* status.
-   *Resolved*: The case has been resolved. A case with this reason has the *Closed* or *Released* status.
-   *Rejected*: The case has been rejected by the owner of the case. A case with this reason has the *Closed* or *Released* status.
-   *Canceled*: The case has been canceled by the portal user. A case with this reason has the *Closed* or *Released* status.
-   *Abandoned*: The case has been left without any answer from the portal user for a long time. A case with this reason has the *Closed* or *Released* status.
-   *Duplicate*: The case is a duplicate of another case with the same problem from your company. A case with this reason has the *Closed* or *Released* status.

</td></tr><tr><td>

## Details Tab

This tab contains an area you can use to describe the case more fully. The area consists of the following:

-   The formatting toolbar, with buttons you can use to edit text, change the typographical treatment of the text, and format it.
-   The text area, where you can enter a detailed description of the case or relevant notes. You can type the description here and edit it by using the buttons on the formatting toolbar.
