# Rollup Rules

Form ID: \(PM207100\)

**Attention:** This form is available only if the *Parent-Child Projects* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

On this form, you create and maintain rollup rules that determine which project transactions of child projects are rolled up to parent projects and how the account groups and cost codes of these transactions are mapped during the rollup. You can set up the following types of rollup rules:

-   *Cost*: A cost-only rollup rule, which you use when the parent project represents the main contract and child projects are used as cost centers. In this case, cost transactions are rolled up from the child projects to the parent project, while revenue and billing remain in the parent project.
-   *Cost and Revenue*: A cost-and-revenue rollup rule, which you use when the parent project is used as a reporting container and child projects keep their own revenue, costs, and billing. In this case, both cost and revenue transactions are rolled up to the parent project for consolidated reporting.

**Important:** You can't delete a rollup rule that is used in a project.

## Account Groups Section

In this section, you can specify how account groups of child project transactions are mapped to account groups of the parent project.

<table id="_46e4ebf8-6480-4500-9c83-d5b2f26a0c63"><thead><tr><th>

Element

</th><th>

Description

</th></tr></thead><tbody><tr><td>

**Use Formula**

</td><td>

A check box that indicates \(if selected\) that the system uses a formula to map source account groups to target account groups. By default, this check box is cleared.

 If this check box is cleared, the account group mapping table is shown. If this check box is selected, the **Account Group Mapping Formula** box appears instead.

</td></tr><tr><td>

**Account Group Mapping Formula**

</td><td>

The formula that determines the target account group for a project transaction during rollup.

 You enter the formula manually or click the Edit button to open the Formula Editor dialog box. For more information on working with formulas in the Formula Editor dialog box, see [Formulas in Inquiry Results: General Information](../Shared/../UserGuide/GI_Using_Formulas_General_Info.md).

 This box appears if the **Use Formula** check box is selected.

</td></tr></tbody>
</table>

The table toolbar has only standard buttons.

<table id="_c3e00228-19be-4f8f-b95f-0838bb1c2de9"><thead><tr><th>

Column

</th><th>

Description

</th></tr></thead><tbody><tr><td>

**Source Account Group**

</td><td>

The account group of the child project transaction. You can select an account group of the following types:

 -   *Income*
-   *Expense*
-   *Off-Balance* if the **Expense** check box is selected for this account group

 One source account group can be mapped to only one target account group.

 If no mapping is specified for this account group, and the child project transaction is rolled up, the system inserts the account group in the **Parent Account Group** column of the transaction on the [Project Transactions](PM_30_40_00.md) \(PM304000\) form.

</td></tr><tr><td>

**Target Account Group**

</td><td>

The account group that the system uses as the parent account group when the child project transaction is rolled up. You can select an account group of the following types:

 -   *Income*
-   *Expense*
-   *Off-Balance* if the **Expense** check box is selected for this account group

 One target account group can be mapped to multiple source account groups.

</td></tr></tbody>
</table>
