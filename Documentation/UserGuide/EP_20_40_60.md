# Import Company Tree {#_cf3939de-e81d-4043-835c-44c667ca9b6a .reference}

Form ID: \(EP204060\)

You use this form to create a hierarchy of workgroups in all branches of your company. The system uses this hierarchy for escalating items that require approval \(such as time cards, requests, requisitions, and purchase orders\) based on the order of groups specified by the tree structure. Items can be escalated from an assigned group up to the next level and eventually to the top. When you create the hierarchy, consider the following aspects of the organization structure:

-   Whether it includes multiple branches
-   Whether you should follow actual approval work flows
-   Whether escalation originating in one of the branches continues up to the top of the tree or stops at a certain workgroup in the same branch

## Form Toolbar { .section}

The form toolbar includes the buttons described below.

|Button|Description|
|------|-----------|
|**Update Tree**|Updates the company tree to display recently added nodes, workgroups, and workgroup members.|

## Company Tree Pane {#1 .section}

In this pane, the existing workgroups are represented as nodes. You can click a node icon to the left of any workgroup to expand the node and view the hierarchical structure of the workgroup. Some workgroups have a one-level list of workgroups, while others can have multiple levels. You can click a node to view the workgroups of this node in the **List of Groups** table, and then click a workgroup in the **List of Groups** table to view the group members in the **Group Members** table.

The toolbar on the pane includes only custom buttons, which are described below.

|Button|Description|
|------|-----------|
|Move to External Node|Moves the selected node one level up in the tree.|
|Move to Internal Node|Moves the selected node one level down in the tree.|

## List of Groups Table {#2 .section}

By using this table, you can create workgroups positioned at the same level in the company tree. As you add a new group to the list, it will appear in the **Company Tree** pane.

For each workgroup, you can specify what wait time is allowed for work item approval or processing and whether escalation may bypass this group. If a work item assigned to any of group members is not processed during the wait time, the work item becomes escalated—that is, visible to upper-level employees so that they can help with solving the problem.

|Button|Description|
|------|-----------|
|Move Node Up|Moves the selected node one position up in the list.|
|Move Node Down|Moves the selected node one position down in the list.|

|Column|Description|
|------|-----------|
|**Workgroup Name**|A name of the workgroup that can serve as an identifier.|

## Group Members Table {#3 .section}

You can use this table to view and update the lists the members of the group selected in the **List of Groups** table.

The table toolbar has only standard buttons.

|Column|Description|
|------|-----------|
|**Contact**|The user account associated with the employee.|
|**Employee ID**|The ID of an employee who is a member of the group.|
|**Employee Name**|The name of the employee.|
|**Position**|The employee position in the company.|
|**Department**|The department of the employee.|
|**Owner**|Select this check box to indicate that this member is the *owner* in the workgroup—that is, an employee who, by default, is assigned work items assigned to the group.|
|**Active**|Select this check box to include the user in the selected workgroup.|
