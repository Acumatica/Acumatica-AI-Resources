# Roll Up Project Transactions

Form ID: \(PM503500\)

**Attention:** This form is available only if the *Parent-Child Projects* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

On this mass-processing form, you can roll up project transactions from child projects to their parent projects. The system links the original child project transactions to the parent project and updates the corresponding parent project budget lines without creating additional project transactions.

## Form Toolbar

The form toolbar includes the buttons described below.

<table id="_62e00432-0784-4456-a59a-4165f7a0f68e"><thead><tr><th>

Button

</th><th>

Description

</th></tr></thead><tbody><tr><td>

**Roll Up**

</td><td>

Rolls up the project transactions which you have selected in the table.

 For each processed project transaction on the [Project Transactions](PM_30_40_00.md) \(PM304000\) form, the system:

 -   Links the original child project transaction to the parent project and determines the parent task, parent account group, and parent cost code based on the project's settings and the rollup rule.
-   Updates the actual amount and quantity of the corresponding parent project budget line and marks the child project transaction as rolled up by selecting the **Rolled Up** check box. The actual quantity of the parent budget line is updated only if the transaction UOM is the same as the budget line UOM or can be converted to it. If the UOM can't be converted, the system updates only the actual amount and displays a warning.
-   Uses the inventory item to find a matching budget line only if the parent project's budget level includes inventory items.

 A transaction can't be rolled up if the target account group or target cost code is inactive.

</td></tr><tr><td>

**Roll Up All**

</td><td>

Rolls up all the project transactions listed in the table.

 For each processed transaction on the [Project Transactions](PM_30_40_00.md) \(PM304000\) form, the system:

 -   Links the original child project transaction to the parent project and determines the parent task, parent account group, and parent cost code based on the project's settings and the rollup rule.
-   Updates the actual amount and quantity of the corresponding parent project budget line and marks the child project transaction as rolled up by selecting the **Rolled Up** check box. The actual quantity of the parent budget line is updated only if the transaction UOM is the same as the budget line UOM or can be converted to it. If the UOM can't be converted, the system updates only the actual amount and displays a warning.
-   Uses the inventory item to find a matching budget line only if the parent project's budget level includes inventory items.

 A transaction can't be rolled up if the target account group or target cost code is inactive.

</td></tr></tbody>

## Selection Area

In this area, you can specify the parent or child project and other criteria to limit the project transactions listed in the table. If neither a parent project nor a child project is specified, the table is empty.

<table id="_2fec1086-b633-47be-9649-b26bc3b86fe2"><thead><tr><th>

Element

</th><th>

Description

</th></tr></thead><tbody><tr><td>

**Parent Project**

</td><td>

The parent project whose child project transactions you want to roll up. You can select a project with the *Parent* project hierarchy position and the *Active* or *Completed* status.

 By default, this box is empty. If you select a parent project, the table lists transactions of its related child projects that meet the other specified criteria.

</td></tr><tr><td>

**Child Project**

</td><td>

The child project whose project transactions you want to roll up. You can select a project with the *Child* project hierarchy position and the *Active* or *Completed* status.

 By default, this box is empty. If a project is specified in the **Parent Project** box, you can select only a child project of that parent project.

</td></tr><tr><td>

**Child Task**

</td><td>

The child project task whose transactions you want to roll up.

 By default, this box is empty. Read-only until you select a project in the **Child Project** box.

</td></tr><tr><td>

**Exclude Rolled-Up and Skipped Transactions**

</td><td>

A check box that you select to exclude transactions that have already been rolled up and transactions that have been skipped according to the applicable rollup rule.

 If this check box is cleared, the table also lists rolled-up and skipped transactions. Transactions that were previously rolled up can be processed again unless they have already been billed in the parent project.

 By default, this check box is selected.

</td></tr><tr><td>

**Account Group**

</td><td>

The account group of the project transactions to be listed. You can select an *Income* or *Expense* account group, or an *Off-Balance* account group for which the **Expense** check box is selected.

</td></tr><tr><td>

**Cost Code**

</td><td>

The cost code of the project transactions to be listed in the table.

 This box appears if the *Cost Codes* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

</td></tr><tr><td>

**Inventory ID**

</td><td>

The inventory item associated with the project transactions to be listed in the table.

</td></tr><tr><td>

**Date Range**

</td><td>

The start and end dates of the project transactions to be listed in the table.

 If both dates are empty, transactions for all dates are displayed.

</td></tr></tbody>
</table>
