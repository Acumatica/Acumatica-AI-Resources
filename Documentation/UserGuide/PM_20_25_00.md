# Project Groups {#_f036b8fc-7db4-46e2-80d7-af8a379cbc5a .reference}

Form ID: \(PM202500\)

If you need to limit the visibility of specific projects to only employees of a particular project team, you can organize projects into *project groups*: groups of projects to which you configure access for a particular set of users by using restriction groups.

By using this form, you can create project groups if the *Administrator*, *AcumaticaSupport*, or *Project Accountant* role has been assigned to your user account on the [User Roles](SM_20_10_05.md) \(SM201005\) form. You can also update the row-level security settings for all projects that are included in a listed project group.

## Form Toolbar { .section}

The form toolbar includes the buttons described below.

The form-specific commands appear on the More menu if the *Row-Level Security* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

|Command|Description|
|-------|-----------|
|**Update Project Restrictions**|Updates the row-level security settings for all projects that are included in the project group that is currently selected in the table. All projects that belong to this project group will have the same restriction settings as the project group currently has.|
|**Manage Restriction Groups**|Opens the [Restriction Groups by Project Group](PM_10_20_20.md) \(PM102020\) form and displays the list of restriction groups associated with the project group that is currently selected in the table.|

## Table { .section}

The table toolbar has only standard buttons.

|Column|Description|
|------|-----------|
|**Project Group ID**|The unique identifier for the project group.|
|**Description**|A short description of the project group.|
|**Active**|A check box that indicates \(if selected\) that the project group can be assigned to projects.|
