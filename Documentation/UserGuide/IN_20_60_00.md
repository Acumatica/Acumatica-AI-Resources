# Posting Classes

Form ID: \(IN206000\)

**Attention:** This form is available only if the *Inventory* feature is enabled on the [Enable/Disable Features](../Shared/../UserGuide/CS_10_00_00.md) \(CS100000\) form.

You use this form to define posting classes for stock and non-stock items. A posting class is a group of settings that provide the default values for the purchase, sales, and inventory transactions with the item and define how these transactions will be posted to the general ledger.

**Important:** The settings defined on this form don't apply to the following documents:

-   Cash sales created on the [Cash Sales](AR_30_40_00.md) \(AR304000\) form
-   Cash purchases created on the [Cash Purchases](AP_30_40_00.md) \(AP304000\) form

By using this form, you can browse through the existing posting classes and modify their properties, add new posting classes, and delete obsolete classes from the system. For more details on posting classes, see [Posting Classes: General Information](Posting_Classes_GeneralInfo.md) and [Inventory Transactions](IN__con_Inventory_Transactions.md).

## Form Toolbar

The form toolbar has only standard buttons.

## Summary Area

In this area, you can enter the identifier and description of a new posting class, or select an existing class to view or modify its details.

|Element|Description|
|-------|-----------|
|**Class ID**|The unique alphanumeric identifier of the posting class. A string up to 10 characters may be used.|
|**Description**|A brief description of the posting class.|

## Posting Settings Section

In this section, you can specify how \(from what sources\) the accounts and subaccounts will be selected for specific-type inventory transactions that involve items of the class.

You can specify the rules of selecting segment values for subaccounts to be used in transactions of various types with items of the posting class. To set up the rule for subaccounts of specific type, for each segment in the subaccount mask, press F3 and select a source of the segment value, which is one of the following options:

-   *I*: The subaccount of this specific type associated with the inventory item. Subaccounts for stock items are specified on the **GL Accounts** tab of the [Stock Items](IN_20_25_00.md) \(IN202500\) form and for non-stock items on the **GL Accounts** tab of the [Non-Stock Items](IN_20_20_00.md) \(IN202000\) form.
-   *W*: The subaccount of this specific type associated with the warehouse. Subaccounts for warehouses are specified using the [Warehouses](IN_20_40_00.md) \(IN204000\) form.

    This option appears only if the *Multiple Warehouses* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

-   *P*: The subaccount \(of this specific type\) associated with the posting class. Subaccounts for posting classes are specified on the current form.
-   *J*: The subaccount of this specific type associated with the project. Subaccounts for projects are specified on the **Defaults** tab of the [Projects](PM_30_10_00.md) \(PM301000\) form.

    This option is available only if the *Projects* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

-   *T*: The subaccount of this specific type associated with the project task. Subaccounts for project tasks are specified on the **Summary** tab of the [Project Tasks](PM_30_20_00.md) \(PM302000\) form.

    This option is available only if the *Projects* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.


For a segment, the character designating the option is repeated as many times as there are characters in the segment. See [Combined Subaccounts: General Information](../ImplementationGuide/config_Combined_Subaccounts_GeneralInfo.md) for additional information.

**Attention:** If your organization uses a predefined list of subaccounts \(that is, if the *By Segmented Keys* lookup mode is selected for the *SUBACCOUNT* segmented key on the [Segmented Keys](CS_20_20_00.md) \(CS202000\) form\), then before you assign any items to this posting class, make sure that all subaccounts that may result from using these rules are added to the list on the [Subaccounts](GL_20_30_00.md) \(GL203000\) form.
