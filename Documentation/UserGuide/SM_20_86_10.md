# Dashboards {#_7ad417fb-294d-4b9b-ac13-40eb2c9b27a5 .reference}

Form ID: \(SM208610\)

You use this form to create and delete Modern UI dashboards and to manage dashboard properties. You can specify a dashboard’s location in the site map and specify access rights to the dashboard. From this form, you can also view the selected dashboard and reset user copies of the dashboard to the original dashboard settings.

For more information on setting up dashboards, see [Administering Dashboards](RPT_Administering_Dashboards_Mapref.md).

## Form Toolbar { .section}

The form toolbar and More menu include the buttons and commands described below.

|Command|Description|
|-------|-----------|
|**Replace Classic Dashboard**|Replaces the Classic UI version of the current dashboard with the Modern UI version.

 This command becomes available when a Classic UI version of the dashboard has been published to the UI and an unpublished Modern UI version of the same dashboard exists.

|
|**Reset All User Copies**|Overrides all user copies of the selected dashboard and restores their original settings.

 This command appears when the selected dashboard was created manually.

|
|**Reset to Predefined**|Restores the original design of the dashboard.

 The command appears only if the selected dashboard is predefined \(provided with Acumatica ERP\) and you’ve made changes to it \(adding, modifying, or deleting widgets\).

|
|**View**|Displays the dashboard whose settings you’re viewing on the form.

 This command is available when you select an existing dashboard or have saved a new one.

|
|**Publish to the UI**|Opens the **Publish to the UI** dialog box, in which you can modify the site map title and screen ID for the dashboard, change the default workspace and category, and specify how access rights are assigned.**Note:** If the Classic UI version of the current dashboard is already published, the system suggests replacing it or publishing the Modern UI dashboard alongside it.

|
|**Unpublish**|Removes the dashboard from the site map, clears the assignment of the screen identifier, and deletes all configured access rights from the database.|

|Element|Description|
|-------|-----------|
|**Site Map Title**|The name that will be shown on the dashboard and in its row on the [Site Map](SM_20_05_20.md) \(SM200520\) form. The name must consist of alphabetic or numeric characters.|
|**Workspace**|The workspace in Acumatica ERP from which the dashboard can be accessed.|
|**Category**|The category under which the dashboard will be displayed in the selected workspace.|
|**Screen ID**|The identifier to be assigned to the dashboard.|
|**Access Rights**|An option button that indicates which access rights should be specified for the newly added dashboard:

 -   **Set to Granted for All Roles**: The system sets the access rights for this dashboard to *Granted* for all user roles in the system.
-   **Set to Revoked for All Roles**: The system sets the access rights for this dashboard to *Revoked* for all user roles in the system.
-   **Copy Access Rights from Screen** \(default\): The system copies the set of the access rights from the form you specify. When you select this option button, a box appears right of it; click the magnifier icon to select the source form in the lookup table.

|
|The dialog box has the following buttons.|
|**Publish**|Publishes the dashboard and closes the dialog box. The system assigns the dashboard the specified screen ID and makes it available in the specified workspace.|
|**Cancel**|Cancels publication and closes the dialog box.|

## Summary Area {#1 .section}

You can use this area to enter or edit the dashboard’s basic settings.

|Element|Description|
|-------|-----------|
|**Name**|The name to be displayed as the dashboard title. For a new dashboard, type a name that describes the data to be shown on this dashboard.|
|**Owner Role**|The role that owns the dashboard. A user with this role assigned can design and delete the dashboard, modify the dashboard’s layout, and edit its settings.**Tip:** If you’ll be designing the dashboard you’re creating, select an owner role assigned to your user account. Otherwise, you’ll be working with your personal copy of the dashboard, and other users won’t see any widgets you add.

|
|**Allow Users to Personalize**|A check box that you select to allow other users with access to the dashboard to copy it and modify its settings for their needs. Changes apply to only their copy; the original isn’t affected.

 By default, this check box is cleared.

|
|**Expose to the Mobile Application**|A check box that you select to make the dashboard available in the Acumatica mobile app connected to this Acumatica ERP site. If the check box is selected, a user of the Acumatica mobile app can view this dashboard on the main menu of the application.

 By default, the check box is cleared.

|
|**Site Map Title**|The name that will be shown on the dashboard and in its row on the [Site Map](SM_20_05_20.md) \(SM200520\) form. The name must consist of alphabetic or numeric characters.|
|**Workspace**|The Acumatica ERP workspace from which the dashboard can be accessed.|
|**Category**|The category under which the dashboard will be displayed in the selected workspace.|

## Visible To Tab {#section_z2h_tjf_kgc .section}

This tab contains a table with all user roles in the system. By using this table, you can manage the access rights of user roles to view the dashboard.

The table toolbar has only standard buttons.

|Column|Description|
|------|-----------|
|**Role Name**|The role.|
|**Role Description**|The role’s description.|
|**Guest Role**|A check box that indicates \(if selected\) that the role is a guest role.|
|**Access Rights**|The access rights of the role for the selected dashboard.

 Restriction levels vary by object type. For some objects, you can specify a more granular level; for others, you can either allow or deny the access. For details, see [User Roles: Restriction Level Options](../Shared/../UserGuide/User_Roles_Access_Levels.md).

|

## Parameters Tab {#section_xcw_yjf_kgc .section}

You use the **Parameters** tab to specify the types of parameters to be used in the Selection area of the dashboard.

The table toolbar has only standard buttons.

|Column|Description|
|------|-----------|
|**Active**|A check box that indicates \(if selected\) that the parameter is active and appears in the Selection area of the dashboard.|
|**Is Required**|A check box that indicates \(if selected\) that this parameter is mandatory. That is, widgets whose data is filtered by this parameter don’t display any data until a user selects a parameter value.|
|**Name**|The name of the parameter, which is used during dashboard creation and editing. It’s used by default as the display name, but you can specify a different display name in the **Display Name** box.|
|**Schema Object**|The data access class \(DAC\) that contains the field whose values are used for the parameter.|
|**Schema Field**|Optional. The field from the selected DAC whose values are used as the parameter values. If no field is specified, the parameter will be a simple text box.|
|**Display Name**|Optional. The name for the parameter that’s displayed in the Selection area of the dashboard. If this column is empty, the system uses the value in the **Name** column.|

## Widgets Tab {#section_s45_3kf_kgc .section}

You use the **Widgets** tab to make a widget active or inactive on the selected dashboard. An inactive widget is not shown on the dashboard in either view mode or design mode. You can also remove a widget from the selected dashboard if you won’t use it anymore.

Also, you can view the row and column that denote the location of the widget on the dashboard.

The table toolbar has only standard buttons.

|Column|Description|
|------|-----------|
|**Active**|A check box that indicates \(if selected\) that the widget is active and visible on the dashboard.|
|**Owner Name**|The name of the user that owns the copy of the widget \(if any\).

 If a user creates a personalized copy of a dashboard, the system creates corresponding copies of the widgets on this dashboard and that user becomes the owner of the copied widgets.

|
|**Caption**|The title of the widget that was specified in the **Widget Properties** dialog box and is shown on the dashboard.|
|**Column**|The number of the column in which the widget is located on the dashboard.

 A widget in the top left corner of a working area has a location of 0, 0: the *0* row and the *0* column. For details, see [Dashboards: Widget Location Within a Working Area](RPT_Administering_Dashboard_Forms_Widget_Coordinates.md).

|
|**Row**|The number of the row in which the widget is located on the dashboard.

 A widget in the top left corner of a working area has a location of 0, 0: the *0* row and the *0* column. For details, see [Dashboards: Widget Location Within a Working Area](RPT_Administering_Dashboard_Forms_Widget_Coordinates.md).

|
|**Widget Type**|The type of the widget.|
|**Source**|The source of the widget’s data, which depends on the widget type and can be one of the following:

 -   For a widget of the *Wiki Page* type: The identifier of the wiki page
-   For a widget of the *Embedded Page* type: The URL of the webpage
-   For widgets of another type: The screen ID of the generic inquiry the widget is based on.

|
|**Widget Class**|The class of the widget, which is used in the source code of Acumatica ERP.|
