# Commitments {#_5d2dcf5c-2595-454a-92ef-067e0139da38 .reference}

Form ID: \(PM306000\)

On this form, you can view the list of internal and external commitments associated with projects; you can also create external commitments. You can use selection criteria to narrow the list of commitments displayed. You can display only the commitments associated with a specific project, account group, project task, cost code, or inventory item—or any combination of these criteria.

**Important:** The form displays commitments associated with the branches to which your user has sufficient access rights.

## Form Toolbar { .section}

The form toolbar includes the buttons described below.

|Command|Description|
|-------|-----------|
|**Create External Commitment**|Opens the [External Commitments](PM_20_90_00.md) \(PM209000\) form, which you can use to create a new external commitment.|

## Selection Area {#1 .section}

You use the elements in this area to select the criteria of commitments to be displayed in the table and to review the totals calculated for the selected commitments.

|Element|Description|
|-------|-----------|
|**Project**|The identifier of the project whose commitments you want to view. If you want to see the commitments associated with all projects, leave this box blank.|
|**Project Task**|The project task for which you want to view commitments. If you want to see the commitments associated with all tasks, leave this box blank.|
|**Account Group**|The account group for which you want to view commitments. If you want to see the commitments associated with all account groups, leave this box blank.|
|**Cost Code**|The cost code for which you want to view commitments. If you want to see commitments associated with all cost codes, leave this box blank.

 The box is available if the *Cost Code* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

|
|**Inventory ID**|The inventory item for which you want to view commitments. If you want to see the commitments associated with all items, leave this box blank.|

## Table {#2 .section}

In the table, you can view the commitments that meet the selection criteria you have specified. The table lists only commitments associated with the branches to which your user has sufficient access rights.

|Column|Description|
|------|-----------|
|**Related Document Type**|The type of the document from which the commitment originates, which can be one of the following:

 -   *Purchase Order, Normal*
-   *Purchase Order, Project Drop-Ship*
-   *Subcontract*

 If the commitment is external, this column is empty.

|
|**Related Document**|The document from which the commitment originates.

 If the commitment is external, this column is empty.

|
|**Vendor**|The vendor specified in the document from which the commitment originates.|
|**Vendor Name**|The name of the vendor specified in the document from which the commitment originates.|
|**Type**|The type of the commitment, which can be one of the following options:-   *Internal*: The commitment originates from a document created in the system.
-   *External*: The commitment has been imported to Acumatica ERP or created manually on the [External Commitments](PM_20_90_00.md) \(PM209000\) form.

|
|**Status**|The status of the commitment, which depends on the status of the **Closed** check box of the corresponding purchase order line on the **Details** tab of the [Purchase Orders](PO_30_10_00.md) \(PO301000\) form or subcontract line on the **Details** tab of the [Subcontracts](SC_30_10_00.md) \(SC301000\) form.

 The status can be one of the following options:

 -   *Open*: The **Closed** check box is cleared in the corresponding purchase order line or subcontract line.
-   *Closed*: The **Closed** check box is selected in the corresponding purchase order line or subcontract line.

|
|**Branch**|The branch of your company with which this commitment is associated.This column is displayed only when the *Multibranch Support* feature or the *Multicompany Support* feature is enabled \(or both features are enabled\) on the [Enable/Disable Features](../Shared/../UserGuide/CS_10_00_00.md) \(CS100000\) form.

|
|**Project**|The project associated with the commitment.|
|**Project Description**|The brief description of the project associated with the commitment.|
|**Project Task**|The project task associated with the commitment.|
|**Account Group**|The account group that was updated by the commitment.|
|**Inventory ID**|The stock or non-stock item associated with the commitment.|
|**Cost Code**|The cost code associated with the commitment.

 The box appears on the form if the *Cost Code* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

|
|**External Ref. Nbr.**|The reference number of the commitment of the *External* type. You can click the link in this column to open the [External Commitments](PM_20_90_00.md) \(PM209000\) form, which you can use to modify or delete the external commitment.|
|**UOM**|The unit of measure of the commitment.|
|**Project Currency**|The project currency.

 This column appears on the form if the *Multicurrency Projects* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form.

|
|**Original Committed Quantity**|The original quantity of the commitment that does not include the changes of change orders.

 For a commitment of the *Internal* type that originates from a purchase order, the original quantity is equal to the quantity of the corresponding line of the purchase order; it also depends on the selection of the **Change Order Workflow** check box for the project in the **Project Properties** section of the **Summary** tab of the [Projects](PM_30_10_00.md) \(PM301000\) form as follows:

 -   If the check box is cleared—that is, the change order workflow is not enabled for the project—and a user changes the quantity of the corresponding line of the purchase order, the system changes the **Original Committed Quantity** accordingly.
-   If the check box is selected—that is, the change order workflow is enabled for the project—and a user changes the quantity of the corresponding line of the purchase order by means of change orders, the system does not change the **Original Committed Quantity**.

 On the [Projects](PM_30_10_00.md) \(PM301000\) form, this quantity is included in the **Original Committed Quantity** of the budget line associated with the same project, project task, account group, and cost code or inventory item if the budget line has a UOM that the system can convert to the UOM of the commitment.

 For more information about how the system selects the unit conversion rules, see [Project Transactions: Update of the Project Budget Structure](../Shared/../UserGuide/Projects_Transactions_Project_Budget_Update.md).

|
|**Original Committed Amount**|The original amount of the commitment that does not include the changes of change orders.

 For a commitment of the *Internal* type that originates from a purchase order, the original amount is equal to the **Ext. Cost** of the corresponding line of the purchase order and also depends on the selection of the **Change Order Workflow** check box for the project in the **Project Properties** section of the **Summary** tab of the [Projects](PM_30_10_00.md) \(PM301000\) form as follows:

 -   If the check box is cleared—that is, the change order workflow is not enabled for the project—and a user changes the **Ext. Cost** of the corresponding line of the purchase order, the system changes the **Original Committed Amount** accordingly.
-   If the check box is selected—that is, the change order workflow is enabled for the project—and a user changes the **Ext. Cost** of the corresponding line of the purchase order by means of change orders, the system does not change the **Original Committed Amount**.

 On the [Projects](PM_30_10_00.md) \(PM301000\) form, this amount is included in the **Original Committed Amount** of the budget line associated with the same project, project task, account group, and cost code or inventory item.

 If the *Retainage Support* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form, the **Original Committed Amount** includes the retained amount because the **Ext. Cost** of the corresponding purchase order line also includes the retained amount.

|
|**Committed CO Quantity**|The total quantity of the cost commitment lines of released change orders that are associated with the commitment. This quantity is calculated as the difference between the **Revised Committed Quantity** and the **Original Committed Quantity**.

 On the [Projects](PM_30_10_00.md) \(PM301000\) form, this quantity is included in the **Committed CO Quantity** of the budget line associated with the same project, project task, account group, and cost code or inventory item if the budget line has a UOM that the system can convert to the UOM of the commitment.

 For more information about how the system selects the unit conversion rules, see [Project Transactions: Update of the Project Budget Structure](../Shared/../UserGuide/Projects_Transactions_Project_Budget_Update.md).

|
|**Committed CO Amount**|The total amount of the cost commitment lines of released change orders that are associated with the commitment. This amount is calculated as the difference between the **Revised Committed Amount** and the **Original Committed Amount**.

 On the [Projects](PM_30_10_00.md) \(PM301000\) form, this amount is included in the **Committed CO Amount** of the budget line associated with the same project, project task, account group, and cost code or inventory item.

|
|**Revised Committed Quantity**|The revised quantity of the commitment. For a the commitment of the *Internal* type, the revised quantity is equal to the quantity of the corresponding line of the purchase order from which the commitment originates.

 For a newly created commitment or for a commitment that no change order affects, this quantity is equal to the **Original Committed Quantity**.

 On the [Projects](PM_30_10_00.md) \(PM301000\) form, this quantity is included in the **Revised Committed Quantity** of the budget line associated with the same project, project task, account group, and cost code or inventory item if the budget line has a UOM that the system can convert to the UOM of the commitment.

 For more information about how the system selects the unit conversion rules, see [Project Transactions: Update of the Project Budget Structure](../Shared/../UserGuide/Projects_Transactions_Project_Budget_Update.md).

|
|**Revised Committed Amount**|The original amount of the commitment. For a commitment of the *Internal* type, the revised amount is equal to the **Ext. Cost** of the corresponding line of the purchase order from which the commitment originates.

 For a newly created commitment or for a commitment that no change order affects, this amount is equal to the **Original Committed Amount**.

 On the [Projects](PM_30_10_00.md) \(PM301000\) form, this amount is included in the **Revised Committed Amount** of the budget line associated with the same project, project task, account group, and cost code or inventory item.

 If the *Retainage Support* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form, the **Revised Committed Amount** includes the retained amount because the **Ext. Cost** of the corresponding purchase order line also includes the retained amount.

|
|**Committed Open Quantity**|The open quantity of the commitment that has not been received yet. For a commitment of the *Internal* type, this is the lowest value of the following differences:

 -   `Committed Revised Quantity – Committed Received Quantity`
-   `Committed Revised Quantity – Committed Invoiced Quantity`

 The committed open quantity becomes zero when the commitment is assigned the *Closed* status.

 On the [Projects](PM_30_10_00.md) \(PM301000\) form, this quantity is included in the **Committed Open Quantity** of the budget line associated with the same project, project task, inventory item, and account group if the budget line has a UOM that the system can convert to the UOM of the commitment.

 For more information about how the system selects the unit conversion rules, see [Project Transactions: Update of the Project Budget Structure](../Shared/../UserGuide/Projects_Transactions_Project_Budget_Update.md).

|
|**Committed Open Amount**|The open amount of the commitment that has not been received yet. For a commitment of the *Internal* type, the calculation of this amount for non-stock items is based on the option selected in the **Close PO Line** box on the **General** tab of the [Non-Stock Items](IN_20_20_00.md) \(IN202000\) form.

 For stock items and for the non-stock items with the *By Quantity* option selected in the **Close PO Line** box, the committed open amount is calculated as follows:

 -   `Committed Revised Amount / Committed Revised Quantity * Committed Open Quantity` if the committed revised quantity is greater than zero

The `Committed Received Amount` is the unit cost multiplied by the received quantity of the corresponding purchase order line or subcontract line.

-   `Committed Revised Amount - Committed Invoiced Amount` if the committed revised quantity equals zero

 For the non-stock items with the *By Amount* option selected in the **Close PO Line** box, the committed open amount equals the lowest value of the following differences:

 -   `Committed Revised Amount - Committed Received Amount`
-   `Committed Revised Amount - Committed Invoiced Amount`

 The committed open amount becomes zero when the commitment is assigned the *Closed* status.

 If the *Retainage Support* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form, the **Committed Open Amount** includes the retained amount because the **Ext. Cost** of the corresponding purchase order line also includes the retained amount.

|
|**Committed Received Quantity**|The received quantity of the commitment. For a commitment of the *Internal* type, this is the received quantity of the purchase order line from which the commitment originates. The system updates the received quantity of the commitment depending on the type of the purchase order line as follows:

 -   If the purchase order line is processed through a purchase receipt, the commitment is updated with the received quantity when the purchase receipt is released.
-   If the purchase order line is billed directly without a purchase receipt being processed, the commitment is updated with the billed quantity when the accounts payable bill is released.

 If purchase order lines and subcontract lines have non-stock items that do not require receipt, these lines do not update the received quantity of the commitment.

 On the [Projects](PM_30_10_00.md) \(PM301000\) form, this quantity is included in the **Committed Received Quantity** of the budget line associated with the same project, project task, inventory item, and account group if the budget line has a UOM that the system can convert to the UOM of the commitment.

 For more information about how the system selects the unit conversion rules, see [Project Transactions: Update of the Project Budget Structure](../Shared/../UserGuide/Projects_Transactions_Project_Budget_Update.md).

|
|**Committed Invoiced Quantity**|The invoiced quantity of the commitment. For a commitment of the *Internal* type, this is the billed quantity of the purchase order line from which the commitment originates.

 On the [Projects](PM_30_10_00.md) \(PM301000\) form, this quantity is added to the **Committed Invoiced Quantity** of the budget line associated with the same project, project task, inventory item, and account group if the budget line has a UOM that the system can convert to the UOM of the commitment.

 For more information about how the system selects the unit conversion rules, see [Project Transactions: Update of the Project Budget Structure](../Shared/../UserGuide/Projects_Transactions_Project_Budget_Update.md).

|
|**Committed Invoiced Amount**|The invoiced amount of the commitment. For a commitment of the *Internal* type, this is the billed amount of the purchase order line from which the commitment originates.

 If the *Multicurrency Projects* feature is enabled on the [Enable/Disable Features](CS_10_00_00.md) \(CS100000\) form and the project currency differs from the billing currency, the committed invoiced amount equals the sum of the amounts of all the related AP document lines multiplied by the rate, where the rate is the conversion rate from the currency of the purchase order from which the commitment originates to the project currency.

 For a commitment of the *Internal* type that originates from a purchase order line, the system updates the **Committed Invoiced Amount** with the **Amount** of the corresponding line of the released accounts payable bill.

|
|**Committed Variance Quantity**|The difference between the values in the **Committed Revised Quantity** and **Committed Invoiced Quantity** columns.|
|**Committed Variance Amount**|The difference between the values in the **Committed Revised Amount** and **Committed Invoiced Amount** columns.|
|**Project Manager**|The project manager of the project associated with the commitment.|
|**Date**|The date of the commitment.|
